# 着色器提取

[English](shader.en.md)

`moly shader` 报告一个包里的着色器**声明了什么、含有什么**：

```sh
moly --unity-version 2022.3.62f3 shader path/to/decrypted/some_bundle --platform 9
```

```
35 shaders, 2545 program records, 925 distinct programs (platform 9)
   597 distinct /   1194 records  <family>
   210 distinct /    312 records  <family>
   ...
```

`--out <文件>` 把完整普查写成 JSON；`--programs <目录>` 把每条程序体单独落盘，按
**着色器 × 平台 × 记录序号**命名；`--json` 只打计数。任何平台的 blob 解析失败，命令以非零状态退出。

## 这一层解的是什么

一个 `Shader` 资产里，编译产物存在 `compressedBlob`：**所有平台的程序首尾相接**放在一个字节数组里，
由 `platforms` / `offsets` / `compressedLengths` / `decompressedLengths` 四条平行表切片，逐平台 LZ4 解压。
解压出来的那段（下称 blob）开头是一张索引表，其后是变长记录。

**索引表里有两类记录，不是一类。** 自记录版本 `202012090`（Unity 2021.2 一线）起：

| 类别 | 内容 |
|---|---|
| program | 关键字集合（全局 + 局部）与编译后的程序体 |
| parameter | 反射表：常量缓冲及其成员、纹理 / 采样器 / 缓冲的绑定槽 |

parameter 记录是**多个变体共享**的那张表。把它当成程序去数，分母会虚高约五分之二——
读出来就是「进度比实际更难推进」。本仓两类分开计数，`parameterRecords` 有自己的名字。

ShaderLab 层面的导出（名字、属性、Pass 标签、渲染状态、fallback）到程序码为止；
反射那一段的字节通常是被跳过的。**本仓读的就是被跳过的那一段**——
一个着色器消费哪些 uniform、它们绑在哪个常量缓冲或纹理槽上，这个信息在别处没有第二个来源：
容器块与 blob 是**分别压缩**的，对整包做原始字节搜索无论名字在不在都返回 0。

## 凭什么信它

引擎自己的读取器在取一条变体时，拿到的是 `记录起点 + 记录长度`。于是**一次正确的解析恰好消费完一条记录**：
字段尺寸读错就会跨界或留洞，账平不了。本仓把这条性质变成校验——`account()` 给出

```
{'total': 2436, 'header': 28, 'records': 2408, 'gaps': [], 'gapBytes': 0, 'overlaps': [], 'balanced': True}
```

`balanced` 为真意味着头部加全部记录正好铺满 blob，既无空洞也无重叠。这不是抽样核对，是**逐字节的账**：
少读一个 4 字节字段就必然留下一个 4 字节洞。

## 分母的纪律

两个数不是一回事，报覆盖率时必须都给：

- **records**——每条 program 记录。
- **distinct programs**——按内容哈希归并后的条数。编译成同一份代码的变体是**一件事**，不是多件。
  实测比值很大：某个包平台 9 的 2,545 条记录只是 925 个不同程序，按记录数评审会把工作量放大近三倍，
  并且盖住「最重的两族占了大头」这个事实。

还有一条比计数更容易错：**只按名字筛出来的集合不是分母。** 命名是作者的习惯，不是分类的定义，
漏掉的恰好是命名不规律的那部分，而它看起来和「不存在」一模一样。
配一条**完全不看名字**的判据交叉——例如「本域的材质到底指向了哪些着色器」——两条口径的差集为 0 才叫穷尽。

## 边界

- **不解释程序**。程序体按 `(着色器, 平台, 记录序号, 内容哈希)` 寻址后原样交还。
  普查一旦开始改写自己报告的东西，就不能再当分母用。
- 一个平台的 blob 解析失败时，**条目保留并带上 error**，不丢弃。丢弃会让解码失败长得像
  「这一族本来就没有程序」，而那是唯一一种绝不能静默的读法。
- 已实跑过的记录版本只有 `202012090`。更早的版本有版本门控的分支，但**没有真实数据跑过**。
- 观测到的每个 blob 每平台都只有**一个** LZ4 分段。多分段的拼接顺序是照字段布局写的，
  **未经样本验证**；`platform_blobs()` 因此把看到的分段数一并报出，让调用方知道自己在哪种情形里，
  而不是默认没事。

## 层次

| 模块 | 职责 |
|---|---|
| `shaders.blob` | 一段已解压 blob 的索引表与记录，附字节账 |
| `shaders.objects` | 从 `Shader` 资产里取出那段 blob：声明形态、Pass 与光照模式、逐平台切片与 LZ4 拼接 |
| `shaders.census` | 一整个包含有什么，按记录数与按不同程序数分别计 |

一个 `Shader` 对象的 `m_Name` 是**空串**，真名在 `m_ParsedForm.m_Name`。
凡是读 `m_Name` 的地方——包括「不解析就先看眼名字」这类图省事的 helper——每个着色器都得到 `""`，
于是按名字筛的普查返回 0，且**和真负结果长得一模一样**。`shaders.objects.shader_name()` 是唯一该用的名字读取入口。
